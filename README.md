# Chanslator 原文件与译文对照工作区

这是一个本地运行的专业翻译审校助手。将 DOC、DOCX 或 PDF 拖进页面后，它会保留原文件、自动判断中英方向、应用术语表并生成正式译文 DOCX。

审校界面不使用 Markdown：左侧直接查看原文件，右侧实时显示和编辑译文。修改停止约 0.65 秒后会自动保存，并同步更新正式译文 DOCX。

## 工作区结构

```text
chanslator/
├─ originals/      # 上传后保存的原文件，绝不被译文覆盖
├─ glossaries/     # 专业术语表和项目翻译规范
├─ workspace/      # 审校状态、段落和任务数据（JSON）
├─ output/         # 正式译文 DOCX
├─ inbox/          # 预留的待处理文件目录
├─ app/            # 本地审校应用
└─ tools/run.py    # 启动入口
```

## 在 VS Code 中启动

1. 用 VS Code 打开本文件夹。
2. 按 `Ctrl+Shift+P`，运行“任务: 运行任务”。
3. 选择 `Chanslator: 启动 Web 工作区`。
4. 首次运行会创建 `.venv` 并安装依赖。
5. 按 `Ctrl+Shift+P`，运行内置命令 `Simple Browser: Show`。
6. 输入 `http://127.0.0.1:8765`。

也可以在 PowerShell 中运行：

```powershell
.\start.ps1
```

## 双击启动，关闭窗口即退出

直接双击项目根目录的 `翻译脚本.cmd`：

- 自动检查运行环境并启动本地翻译服务。
- 自动打开桌面 HTML 审校窗口。
- 关闭该窗口时，会先提交当前编辑内容，然后自动结束本地服务。
- 不会在关闭后继续保留翻译后台进程。

普通 `.html` 受浏览器安全机制限制，不能自行启动本机程序，因此这里使用一键启动文件承载相同的 HTML 页面。首次双击时可能需要联网安装依赖，之后可直接打开。

## 日常工作流

1. 将一个或多个 DOC、DOCX、PDF 拖到页面任意位置。
2. 系统立即保存原件、提取可翻译文字并判断中英文方向。
3. 勾选“上传后立即翻译”时会直接开始翻译。
   第一段会单独优先翻译，随后默认每 3 段返回一次；已完成的译文会立即出现在右侧，可以边翻译边校对。
   模型设置中可限制每次最多段落数和最大字符数；超过上限的长段落会自动切分成多次请求，再合并为同一段译文。
4. 默认使用“原文件 + 译文”模式：左侧原版面，右侧译文。
5. 右侧默认连续显示全部译文，标题栏会显示“已显示数量 / 总段落数”；每段右侧点击“原”可按需展开对应原文。
6. 也可以切换到“逐段精确对照”，使用蓝色原文栏和绿色译文栏严格逐段并排；悬停或编辑时整段高亮。
7. 在右侧修改译文；系统自动保存，并更新 `output/` 中的正式 DOCX。
8. 点击“下载译文 DOCX”后，系统会在 `output/` 保存最新版、显示项目保存路径，并打开标准另存为窗口；不会自动向桌面复制文件。
9. “最近文档”中的每条记录右侧都有删除按钮；删除仅移除工作区记录，原件和译文仍会保留，任务数据会暂时移动到 `workspace/.trash/`，并在程序关闭时随其他 `document.json` 一并清除。
10. 关闭程序时会先把当前已完成的部分译文写入 `output/`，随后自动清除 `workspace/` 中所有 `document.json` 记录；原件和译文文件不受影响，下次启动时“最近文档”列表为空。

## 原文件预览

- PDF：使用内置 PDF.js 分页显示；超大 PDF 只渲染当前位置附近的页面，离开可视区域后释放画布，避免一次加载全部页面。
- DOCX：使用项目内置的本地浏览器渲染器显示文字、表格、分页、页眉页脚和图片，无需安装 LibreOffice，也不访问 CDN。
- 勾选“同步翻页”后，滚动左侧原件会带动右侧译文，滚动右侧译文也会带动左侧原件。程序会读取 PDF/DOCX 每页的实际文字，在本地建立“翻译段落 → 原件页码和页内位置”的索引，不直接比较左右像素高度，因此能补偿中译英变长、英译中变短以及各页文字密度不同造成的偏差；仍可切换到“逐段精确对照”复核。
- DOCX 的复杂域、SmartArt、嵌入对象等特殊 Word 功能可能与 Word/WPS 略有差异，可点击“打开原文件”复核。
- 老式 DOC：属于不同的二进制格式，仍需 LibreOffice 转换，或先在 Word/WPS 中另存为 DOCX。

## DOC/DOCX 中的图片

- 译文 DOCX 从原文档副本生成，只替换文字节点。
- 普通图片、页眉图片、表格内图片及其尺寸会随原文档保留。
- 纯图片段落不会进入翻译队列。
- 图片内嵌文字不执行 OCR，也不会翻译。
- 文本框、复杂域、批注等 Word 特殊对象可能仍需人工复核。

## PDF 说明

PDF 原件始终保存在 `originals/`，译文另存为 DOCX。文本型 PDF 可直接处理；扫描 PDF 需要先使用 Acrobat、ABBYY 或 OCRmyPDF 添加文本层。

## 内置开源组件

DOCX 页面预览使用 `docx-preview 0.3.6`（Apache-2.0）和 `JSZip 3.10.1`（MIT/GPLv3 双许可证，本项目按 MIT 使用）；PDF 页面预览使用 `PDF.js 3.11.174`（Apache-2.0）。组件与许可证均保存在 `app/static/vendor/`。

## 配置翻译模型

点击页面右上角“模型设置”，填写接口协议、网关地址、模型名称和 API Key。设置只保存在本机 `.env`，并且服务默认只监听 `127.0.0.1`。

默认每次最多提交 3 个段落、6000 个原文字符，并允许每个模型请求失败后自动重试 5 次。这些上限都可在“模型设置”中调整；单个段落超过字符上限时会自动切分为多个请求，翻译完成后再合并回同一译文段落。

网络超时、HTTP 429 限流、HTTP 408/409/425 和 5xx 网关故障会采用指数退避自动重试，并遵守服务端的 `Retry-After`。重试期间页面会显示次数、等待时间和失败原因。HTTP 400、401、403、404 等地址、鉴权或请求配置错误会立即停止，避免无意义循环。

### CCSwitch / API 网关

- 一般选择 `OpenAI 兼容 / CCSwitch 网关`。
- 网关地址可以填基础地址，例如 `http://127.0.0.1:端口/v1`；也可以直接填以 `/chat/completions` 结尾的完整地址。
- 模型名称填写 CCSwitch 或网关中实际提供的模型 ID。
- 本地网关不要求鉴权时，API Key 可以留空。
- CCSwitch/直连网关建议关闭“使用系统代理”；系统代理拦截网关连接时可能返回 403。
- 如果网关提供的是 Anthropic Messages 接口，改选 `Anthropic Messages 兼容网关`；基础地址和以 `/messages` 结尾的完整地址均可使用。

## 术语标准化

`glossaries/terms.csv` 当前只有表头，没有预置术语。可以直接填写，或加入更多 CSV、TSV、JSON 术语表。项目级语言风格写入 `glossaries/style_guide.md`。详细格式见 [glossaries/README.md](glossaries/README.md)。
