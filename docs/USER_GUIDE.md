# fxxk_file 使用手册

本文档面向日常使用者，介绍从启动、模型配置、文档翻译到审校和导出的完整流程。

## 1. 启动和退出

最简单的方式是双击项目根目录的 `翻译脚本.cmd`。首次运行会自动创建 Python 虚拟环境并安装依赖，耗时取决于网络速度。以后启动通常会直接打开桌面窗口。

也可以运行 `start.ps1`，然后访问 <http://127.0.0.1:6670> 使用浏览器版。

请通过关闭桌面窗口或在 PowerShell 中按 `Ctrl+C` 正常退出。退出时程序会：

1. 停止尚未结束的翻译任务。
2. 把当前已经返回的部分译文写入 `output/`。
3. 清除 `workspace/` 中的任务记录。
4. 保留 `originals/` 中的原件和 `output/` 中的译文。

因此，重新启动后“最近文档”为空是正常行为，不代表原件或译文丢失。

## 2. 配置翻译接口

点击右上角“模型设置”。

### OpenAI 兼容 / CCSwitch

- 接口协议选择“OpenAI 兼容 / CCSwitch 网关”。
- 地址可填写基础地址，例如 DeepSeek 官方 `https://api.deepseek.com/v1`，程序会补上 `/chat/completions`。
- 也可以直接填写以 `/chat/completions` 结尾的完整地址。
- 模型名称必须是网关实际支持的模型 ID。
- 云端服务通常需要 API Key；本地无鉴权网关可以留空。

### Anthropic Messages 兼容

- 接口协议选择“Anthropic Messages 兼容网关”。
- 地址可填写基础地址，也可填写以 `/messages` 结尾的完整地址。
- 填写相应模型名称和 API Key。

### 请求参数

- 每次最多段落数：范围 1–10，越大请求次数越少，但单次失败影响的段落更多。
- 单次最大原文字符数：范围 500–20000。超长段落会自动拆分，翻译后再合并。
- 失败自动重试次数：范围 0–10。超时、429、408/409/425 和部分 5xx 错误会指数退避重试。
- 使用系统代理：只有接口确实需要系统代理时才开启；本地网关通常应关闭。
- 译文中文：控制中文译文使用简体还是繁体，详见第 4 节的「繁简转换」。

HTTP 400、401、403、404 等地址、鉴权或请求配置错误通常不会反复重试，需要修改设置后重新翻译。

## 3. 上传文档

把文件拖到页面任意位置，或点击上传区域选择文件。支持同时选择多个文件。

支持格式：

| 格式 | 处理方式 | 注意事项 |
|---|---|---|
| DOCX | 直接提取并预览 | 支持正文和表格文字，复杂 Word 对象需复核 |
| DOC | LibreOffice 转换后处理 | 未安装 LibreOffice 时无法读取 |
| PDF | pdfplumber 快速提取，缺失时回退 pypdf | 扫描件需要先 OCR；译文不保留 PDF 版式 |

单文件上限为 80 MB。上传成功后，原文件会以带任务 ID 的名称保存到 `originals/`，不会被译文覆盖。

“上传后立即翻译”默认勾选。若只想先检查分段、语言方向或模型设置，可取消勾选，上传后再点击“翻译空白段落”。

### 大文件与多栏 PDF

- 超过百页的 PDF 会先由本机解析再显示，几秒钟内没有反应属于正常现象；解析完成后段落会一次性出现。
- 默认抽取方式速度优先，同一份 134 页标准征求意见稿会得到约 156 个段落。
- 如遇到双栏排版的报告、论文，可在 `.env` 中设置 `TRANSLATION_PDF_LAYOUT_MODE=layout`，程序会按文字坐标重建行与分栏，阅读顺序更接近原文，代价是解析时间约增加 2.5 倍。
- 段落很多时，译文行高按需计算，滚动到哪一段就补算哪一段，因此长文档首次打开不会长时间卡顿。

### 扫描件自动 OCR

左侧勾选「扫描件自动 OCR（离线）」后，程序会对没有文字层的 PDF 在**本机**用 RapidOCR 识别，识别结果直接作为原文进入翻译流程，文档不会上传到任何 OCR 服务。

- 该功能默认不安装，需要执行 `.\.venv\Scripts\python.exe -m pip install -r requirements-ocr.txt`（约 200 MB）。
- 未安装时该勾选框会置灰，可在“模型设置”中查看可用状态；PDF 仍会提示“需要先 OCR”。
- 每份文件最多识别前 80 页，识别速度取决于 CPU，扫描页较多时请耐心等待。
- 识别结果按行高聚合成段落，错误率高于文本型 PDF，建议在逐段对照视图中复核数字、专有名词和单位。

## 4. 语言方向和翻译

程序会依据前 30 个文本块自动判断中文或英文，并自动选择相反的目标语言。上传后仍可在工具栏手动修改源语言和目标语言。

点击“翻译空白段落”只会处理尚无译文且未锁定的段落，不覆盖已有内容。第一段会优先单独返回，随后按设置中的批量大小继续翻译，方便尽快开始审校。

如需修改已生成的段落，可直接人工编辑，或使用该段的重译操作。锁定的段落不会被批量翻译覆盖。

### 繁简转换

左侧「译文中文」控制中文译文使用哪种字形，同时也会写入模型提示词，减少翻译后返工：

| 选项 | 效果 |
|---|---|
| 跟随目标语言（简体） | 目标语言为中文时把译文转换成简体；其他情况不转换 |
| 简体中文 | 始终转换为简体 |
| 繁體中文 | 始终转换为繁體（使用台湾用词习惯，例如「軟件 → 軟體」） |
| 不做转换 | 保持模型原始输出 |

转换由本机的 zhconv 完成，不使用模型额度。工具栏的「繁简转换」按钮可以对整篇文档立即重跑一次转换：

- 只处理包含中文的译文段落，英文段落不受影响。
- 已审校段落也会被改写，其状态会退回「已编辑」，需要重新确认。
- 若左侧未安装 zhconv（同时「模型设置」会标注不可用），按钮不起作用。

### 停止翻译

翻译过程中工具栏下方会出现进度条，右侧是「停止翻译」。停止后：

- 已经翻译完成的段落全部保留，不会因为停止而丢失。
- 仍处于排队或翻译中的段落退回「待翻译」，可以稍后继续。
- 文档状态回到「待翻译」，可以继续编辑、批量操作或重新开始翻译。

程序重启后若看到段落一直停在「等待翻译」，点击一次「停止翻译」即可把这些段落释放回可编辑状态。

## 5. 两种审校视图

### 原件版面对照

左侧显示原始文件版面，右侧连续显示译文。适合参考标题、表格、图片和分页位置。

- 拖动中间分隔条调整宽度，双击恢复均分。
- 左侧可缩放原文预览。
- 右侧可调整译文字号。
- 开启“同步翻页”后，左右滚动会按照文档文字位置互相定位。
- 每个译文段落可按需展开对应原文。

PDF 预览采用按需渲染，超大文件不会一次载入全部页面。DOCX 由本地内置渲染器显示，不需要访问外部 CDN。

### 逐段精确对照

原文和译文严格按段并排，适合逐句核对。编辑或悬停时会突出显示整行，便于确认对应关系。

## 6. 双文件对比与差异高亮

从顶部「功能」菜单选择「双文件对比」，一次选择两份同类型文件（文档 + 文档，或图片 + 图片）。

- 勾选工具栏的「高亮差异」后，两份文档的抽取文本会在下方做行级比对：绿色为新增行，红色带删除线为删除行，灰色为相同行。
- 差异只在浏览器本地计算；两份文件会先经本机服务抽取文本，不会发送到模型服务。
- 比对遵循阅读顺序，因此用 pdfplumber 抽取的双栏 PDF 差异结果比按页拼接的文本更准确。
- 图片对比不支持差异高亮，勾选后不会显示差异面板。
- 对比为只读查看，不会改动原文件。

## 7. 文件转换

从顶部「功能」菜单选择「文件转换」。左侧列出六组工具，选中后在中间填写参数，右侧显示结果；需要额外依赖的工具会置灰并说明安装命令。所有转换都在本机服务上完成，文件不会上传到第三方。

### 中文排版

修掉从旧系统导出的文本问题：

| 转换方式 | 用途 |
|---|---|
| 检测编码并转为 UTF-8 | 自动识别 GB18030、Big5、Shift-JIS 等编码并转成 UTF-8，结果标题会显示检测到的编码 |
| 全角 → 半角 | `ＡＢＣ１２３` → `ABC123`，同时把全角空格转为普通空格 |
| 半角 → 全角 | 反向转换 |
| 英文标点 → 中文标点 | 逗号、句号、括号、书名号等改为中文标点；数字与版本号中的小数点会被保留 |
| 中文标点 → 英文标点 | 反向转换，并按英文习惯补空格 |

可以直接粘贴文本，也可以上传 `.txt`、`.csv`、`.md` 等文件（上传时优先使用文件内容）。

### 表格互转

CSV、TSV、JSON、Markdown 表格与 HTML 表格之间任意互转。来源格式选「自动识别」时会根据内容判断，结果标题会显示实际使用的来源格式。JSON 需要是对象数组（`[{"a": 1}]`），对象里的键会作为表头。

### 字幕互转

- **格式互转**：SRT、VTT、ASS、SSA、LRC 之间互转，结果里可以直接下载。
- **双语合并**：两份字幕合成一条双语字幕。对齐按时间轴而不是序号，因此其中一份有重排或漏句时不会整体错位。
- **双语拆分**：把双语字幕按行拆成两条独立的 SRT，每条都提供单独下载。

### 文档互转

- **HTML → Markdown**：粘贴 HTML 源码或上传 `.html`，脚本与样式会被丢弃。
- **DOCX → Markdown**：上传 `.docx`，按文档顺序输出标题、列表、引用与表格。
- **Markdown → DOCX**：粘贴 Markdown 并直接下载生成的 DOCX，支持标题、列表、引用、代码块与表格。

### PDF 页面

| 操作 | 说明 |
|---|---|
| 合并多个 PDF | 按选择顺序拼接 |
| 按页拆分为多个文件 | 每页一个 PDF，打包成 ZIP 下载 |
| 提取指定页 | 页码范围如 `1-3,7`，留空为全部 |
| 删除指定页 | 不能删除全部页面，需要拆分时请用上一项 |
| 旋转页面 | 顺时针 90°、180° 或逆时针 90°，可只作用于指定页 |
| 添加文字水印 | 对角灰色水印，支持拉丁字符；中文水印需要嵌入字体，暂不支持 |

### 数字与拼音

- **金额 → 中文大写**：`1234.56` → `壹仟贰佰叁拾肆元伍角陆分`，按十进制字符串解析，不会出现浮点误差。
- **整数 → 中文数字**：`10005` → `一万零五`，只接受整数。
- **汉字 → 拼音**：可选不带声调、带声调、数字声调或仅首字母；非汉字内容原样保留。

## 8. 编辑、保存和审校

直接在译文输入框中编辑。停止输入约 0.65 秒后，程序会自动保存任务状态，并重新生成 `output/` 中的译文文件。顶部「已保存」左侧的小圆点会显示当前状态：灰点为空闲、黄点为保存中、绿点为已保存、红点为保存失败。

常用段落操作包括：

- 重译：只重新调用模型翻译当前段落。
- 锁定/解锁：锁定后批量翻译不会改动该段。
- 标记已审校：记录该段已经人工确认，同时自动锁定该段。
- 展开原文：在连续译文视图中查看对应原文。

### 段落筛选与批量操作

译文区标题下方是筛选栏，按状态统计并筛选段落：全部、待翻译、机器译文、已编辑、已审校、已锁定。每个筛选项后面的数字是实时计数，切到某个筛选后译文表只显示该状态的段落，页脚会显示「筛选出 N / 总数」。

筛选之后用右侧「批量操作」菜单执行：

| 操作 | 效果 |
|---|---|
| 锁定所选段落 | 批量翻译不会覆盖这些段落 |
| 解锁所选段落 | 解除锁定，是唯一会改动已锁定段落的操作 |
| 标记为已审校 | 无译文的段落会跳过；成功标记的段落同时锁定 |
| 撤销审校状态 | 已审校段落退回「已编辑」并解锁 |
| 清空所选译文 | 只清空译文，原文保留；已锁定段落不受影响，需要二次确认 |

批量操作由服务端按筛选条件执行，因此即使文档很长、界面只渲染了部分段落，选中的范围也始终是完整的。典型的审校流程是：先筛「待翻译」确认没有漏译，再筛「机器译文」逐条确认后批量标记审校，最后用「已锁定」筛一遍确认没有误锁。

### 键盘快捷键

按 `?` 或点击顶部的快捷键按钮可以打开快捷键面板，面板只列出当前工作区真正可用的组合键。

| 快捷键 | 功能 |
|---|---|
| `?` | 打开快捷键面板 |
| `Ctrl+F` | 在当前工作区搜索 |
| `Ctrl+O` | 打开待翻译文档 |
| `Ctrl+1` / `Ctrl+2` | 切换「原件版面对照」/「逐段精确对照」 |
| `Ctrl+D` | 下载译文 DOCX |
| `Alt+↑` | 跳到上一段 |
| `Alt+↓` | 跳到下一段 |
| `Ctrl+Enter` | 将当前段标记为已审校 |
| `Esc` | 关闭面板或退出全屏 |

关闭程序前最好等待顶部状态显示“已保存”。桌面版正常关闭时也会主动提交当前编辑内容。若保存失败，顶部会显示红色状态点并在提示条中给出原因。

## 9. 下载和本地文件

点击“下载译文 DOCX”后，程序会先把最新内容写入 `output/`，再打开系统另存为窗口。无论是否在另存为窗口中选择其他位置，项目目录内都会保留一份输出文件。

默认文件名类似：

```text
原文件名_12位任务ID_译文.docx
```

对于 DOC/DOCX，译文从原文档副本生成，只替换已提取的文字节点，所以普通图片、表格、页眉页脚和大部分版式会保留。对于 PDF，程序创建新的 DOCX，并按顺序写入翻译后的段落。

## 10. 最近文档与删除

“最近文档”显示当前运行会话中的任务。点击记录旁的删除按钮只会移除工作区任务记录：

- 原件继续保留在 `originals/`。
- 已生成译文继续保留在 `output/`。
- 任务记录暂时移动到 `workspace/.trash/`，程序关闭时其中的状态文件会被清理。

这个删除操作不等于删除原文件或译文。如果需要彻底删除，请在确认文件无用后手动处理对应目录。

## 11. 术语表

程序会扫描 `glossaries/` 下的 CSV、TSV 和 JSON 文件，并只把当前批次原文中出现的相关术语发送给模型。文件修改后下一批请求就会读取新内容，无需重启。

CSV/TSV 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `source` | 是 | 原语言术语 |
| `target` | 是 | 指定译法 |
| `source_lang` | 否 | `zh` 或 `en` |
| `target_lang` | 否 | `en` 或 `zh` |
| `domain` | 否 | 专业领域 |
| `notes` | 否 | 用法、上下文或禁用译法 |

示例：

```csv
source,target,source_lang,target_lang,domain,notes
术语表,glossary,zh,en,localization,统一使用 glossary
审校,review,zh,en,localization,不要使用 proofreading
```

JSON 示例：

```json
{
  "terms": [
    {
      "source": "术语表",
      "target": "glossary",
      "source_lang": "zh",
      "target_lang": "en",
      "domain": "localization",
      "notes": "统一译法"
    }
  ]
}
```

设置了语言方向的术语可自动反向使用。更多说明见项目中的 `glossaries/README.md`。

## 12. 风格指南

在 `glossaries/style_guide.md` 中写入项目级要求，例如：

```markdown
- 使用正式、简洁的商务英语。
- 标题采用 sentence case。
- 日期统一写作 YYYY-MM-DD。
- 产品名称 fxxk_file 不翻译。
```

风格指南会随每批翻译请求发送给模型。建议使用短而明确、可以直接执行的规则，避免放入无关背景资料。

## 13. 故障排查

### 双击后没有窗口

在 PowerShell 中运行 `.\start.ps1` 查看错误信息。确认 Python 已安装，并且 `python --version` 可用。首次安装依赖需要可访问 Python 包源。

### 提示端口已被占用

关闭其他 fxxk_file 窗口或占用 6670 端口的程序。也可以修改 `.env`：

```dotenv
APP_PORT=6671
```

### 模型设置显示已配置，但翻译失败

“已配置”只表示地址、模型名和协议已经填写，不代表接口连通。依次检查：

1. 协议是否与网关一致。
2. 地址是否包含正确的版本路径，如 `/v1`。
3. 模型 ID 是否存在且有权限。
4. API Key 是否正确。
5. 本地网关是否应关闭系统代理。

### 返回 429 或 5xx

程序会自动重试并在页面显示等待时间。持续出现 429 时，应降低批量大小、降低调用频率，或检查服务额度。

### PDF 提示没有可提取文字

文件很可能只有扫描图片。三种处理方式：

1. 勾选左侧「扫描件自动 OCR（离线）」后重新上传（需先安装 `requirements-ocr.txt`）。
2. 使用 Acrobat、ABBYY、OCRmyPDF 等工具添加文本层，再重新上传。
3. 在先前的版本中若曾经能提取文字，则升级后仍会回退到 pypdf，不会因为缺少 pdfplumber 而失败。

### 导入大 PDF 时页面长时间无响应

这是解析阶段而不是死机。可以先确认文件页数与体积：百页左右的 PDF 通常需要几秒到十几秒。

- 如果导入后段落数异常多（例如 134 页变成 1500 多段），说明使用了旧的 `layout=True` 分段方式，升级到 v1.7.0 后重新导入即可恢复正常数量。
- 若确实需要多栏阅读顺序而手动设置了 `layout`，解析时间会相应增加，请等待状态栏出现段落后再操作。

### DOC 无法读取或预览

安装 LibreOffice，或在 Word/WPS 中把文件另存为 DOCX。旧版 DOC 与 DOCX 是不同的文件格式，不能只修改扩展名。

### DOCX 译文出现版式差异

普通图片和段落样式会尽量保留，但图片内文字不做 OCR，文本框、批注、SmartArt、嵌入对象、复杂域等内容可能无法完整处理。最终交付前请在 Word/WPS 中人工复核。

### 重启后最近文档消失

这是当前程序的会话清理机制。请到 `originals/` 和 `output/` 查找保留的原件与译文。

## 14. 数据与安全

- 原件、译文、术语和配置保存在本机项目目录。
- 待翻译文本、匹配到的术语和风格指南会发送到所配置的模型服务。
- 扫描件 OCR 与繁简转换都在本机完成，不会发送到第三方服务。
- Markdown 查看、对比差异高亮同样只在浏览器本地运行，文件不会上传。
- API Key 保存在 `.env`；请限制该文件的访问权限，不要上传到代码仓库或发送给他人。
- 服务默认仅监听 `127.0.0.1`。若改为局域网监听，应额外配置防火墙、反向代理认证和 HTTPS。
